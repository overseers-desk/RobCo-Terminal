# Windows SSH Clients: reaching a remote machine from Windows

Snapshot taken August 2026.

A client here is a program a person installs on Windows to reach a remote machine over SSH: an interactive shell, file transfer, or a managed set of connections to many hosts. Windows's own OpenSSH client and Windows Terminal are in the table because they are what every other entry has to beat, not because either was built to compete in this field. A tool whose SSH reach is a means to another end, such as an editor's remote-development mode, is in the table only where that reach is its primary marketed capability; where SSH is peripheral to another transport, incomplete on Windows specifically, or bolted onto a local terminal emulator rather than built for it, the tool is named below the table instead.

Capabilities are as their authors and vendors describe them in pricing pages, docs and repos, not independently re-verified beyond what a second source corroborated; cells that could not be confirmed read "unconfirmed", and a claim resting on vendor marketing alone is marked as such. Release dates and star counts are approximate and omitted where unknown.

Re-snapshot trigger: Microsoft changing the OpenSSH client's default-install status on Windows, a client in this table being discontinued or acquired, a new client reaching adoption comparable to the incumbents, or six months elapsed.

## Adjacent tools, and why they are not in the table

**WezTerm** supports SSH through config-defined "SSH domains" that can auto-populate from `~/.ssh/config`, but it is a local terminal emulator with SSH attached: full multiplexing over that connection needs a companion `wezterm` binary installed on the remote host. **Warp** reached general availability on Windows in 2026 (open source, MIT plus AGPLv3), but its dedicated SSH features, a project explorer and native remote file reads, remain macOS and Linux only per its 2026 issue tracker; Windows SSH support is basic. **Windows Admin Center** is a browser-based server-management gateway whose primary transport is PowerShell Remoting and WinRM; SSH appears only peripherally, for console access to Linux targets. **ConEmu** and **Cmder** are console-window wrappers that can host `ssh.exe` inside a tab, but supply no SSH-specific session manager, agent integration, or persistence beyond what the wrapped binary already does; ConEmu shows sparse recent maintenance.

Links: wezterm.org/ssh.html; warp.dev; learn.microsoft.com/windows-server/manage/windows-admin-center; conemu.github.io.

## Where the field is moving

PuTTY keeps a real, security-driven release cadence: 0.83 (2025-02-08), 0.84 (2026-05-22), 0.85 (2026-08-16, fixing a Pageant use-after-free among other CVEs). The 0.85 date is corroborated by a forum thread quoting the changelog; a direct fetch of the vendor's own changelog page did not return content on retry, so treat the exact date as sourced secondhand rather than read directly. Comparison roundups from 2026 consistently frame PuTTY as the baseline everyone already knows, not as an exciting pick, and frame Windows Terminal with the built-in OpenSSH client as the "do not want to install anything" default, the free floor the rest of the field is measured against. MobaXterm keeps being recommended specifically for power users and system administrators wanting X11, multiple protocols and tabs bundled into one app; it stays closed source, so there is no GitHub activity signal to check its momentum by, only winget version numbers (around 26.x through 2026).

Tabby and WindTerm are paired against each other in comparison pieces as the two live open-source contenders: Tabby has the broader plugin and customisation ecosystem but carries Electron's overhead, WindTerm claims better raw performance but is only partially open by the project's own description. Tabby shows real activity: about 74.2k GitHub stars, 4.2k forks, ongoing 2026 plugin releases and issues. KiTTY and SuperPuTTY both show stalled release cadences: KiTTY's last release was 2023-09-17, SuperPuTTY's last formal stable release was 2021-10-26, though both repositories still receive user issues into 2024 and 2025. mRemoteNG is the opposite case, fully free and still showing repository activity into August 2026 with an active nightly build channel alongside stable releases.

Termius shows real product-investment velocity: quantum-resistant cryptography (ML-KEM, ML-DSA) added April 2026, an experimental AI agent feature launched August 2025, a Workspaces and Focus Mode release in January 2025. The company behind it is small by the numbers found, roughly 28-33 employees and $4.25M raised, so "growing" here is evidenced at the product-surface level, not by any independently verified user-count growth. VS Code Remote-SSH carries the single hardest number found in this whole survey, 36,991,521 installs on the Marketplace at time of check; a secondary, unverified source claims 50M+ installs for the whole Remote Development extension family, which was not independently confirmed.

## What is free already, and what genuinely is not

A basic single-session SSH connection is fully covered free: Windows's own OpenSSH client plus Windows Terminal, both at no cost, do this completely. A tabbed and split multi-session terminal is also covered free twice over: Windows Terminal supplies it out of the box, and Tabby, also free and MIT-licensed, goes further with a native `~/.ssh/config` importer and the most complete cross-platform agent support found anywhere in this survey. Centralised multi-host session management with vaulted credentials, the niche paid tools like Royal TS and Termius's Team tier compete in, is substantially matched free by mRemoteNG: an AES-256 credential vault, Windows Credential Manager integration, and hierarchical host grouping, agent-forwarding reliability aside. Cosmetic theming is solved free several times over, in Windows Terminal, Tabby, WindTerm, and community PuTTY colour-scheme repositories; nobody has to pay for a terminal that looks good.

What is not covered free, or by anything in this survey, is a Windows-native way to get a real SSH session that survives both the client closing and the network dropping, without the user manually running tmux or mosh on the remote and without dropping into WSL. Every reconnect feature found in this table, paid or free, restores the transport rather than the remote shell's live state unless the remote side is already running a multiplexer of its own; WSL paired with tmux or mosh is the one path that genuinely delivers this, and it is free, but it is a Linux-tooling answer rather than a Windows-native GUI one. A second real gap: reliable, first-party interoperability between Windows's three mutually incompatible SSH-agent protocols (Windows OpenSSH's named pipe, Pageant's named pipe, Cygwin's socket) is patched over by third-party bridge tools rather than solved by any vendor surveyed here, free or paid. A third, narrower gap: mRemoteNG's own SSH agent forwarding is documented as broken in a specific, still-open way even though the pieces it wraps work individually.
